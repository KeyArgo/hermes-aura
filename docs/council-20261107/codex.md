Aura’s best chance is to make one distinctive claim undeniable: **the desktop responds visibly to both music and a real Hermes task, while remaining comfortable to use**. The competitor scores are too thin to optimize against precisely.

1. **Prove the real agent-to-backdrop flow.** Make thinking, tool use, approval and completion visually distinct enough to recognize with the video muted. Show a small, readable state label so judges can connect cause and effect; verify it comes from real hooks, not a staged mood command. Rehearse a task that reliably reaches approval.  
   **Why it moves the score:** Demonstrates the creative distinction and practical value in seconds.  
   **Rough effort: 6–10 hours.**

2. **Harden the actual Linux experience.** Exercise startup, silence, missing capture, server restart, theme switching and shutdown in Hermes Desktop. Investigate the two-server setup specifically: confirm hooks, controls and backdrop reach the same live state. Provide an obvious off switch, preserve chat contrast, and verify reduced-motion behavior and flash limits across the rendered presets—not just the surrounding UI.  
   **Why it moves the score:** A spectacular demo cannot recover from a frozen gateway or an uncontrollable backdrop.  
   **Rough effort: 12–18 hours.**

3. **Build a small, closable Studio.** Deliver X, Esc and outside-click dismissal; preset search/selection and lock; visibility, motion and off controls. Make selecting a preset immediately change the real backdrop. Remove the permanent pane and separate page only if the replacement works reliably in the real host.  
   **Why it moves the score:** Gives judges ownership of the visual experience and improves polish.  
   **Rough effort: 8–14 hours.**

4. **Rehearse and package the exact submission.** Freeze the revision early. On a clean Linux profile, follow the submitted install instructions, enable Aura, run the demo, disable it and restart Hermes. Record the 60-second video from that revision; include a short troubleshooting section and the tested Hermes version.  
   **Why it moves the score:** Turns the working local setup into something judges can reproduce.  
   **Rough effort: 6–8 hours.**

For roughly four working days, budget **40% reliability, 30% demo and proof, 20% Studio, 10% submission rehearsal**. Protect the rehearsal time. The Studio plan’s half-day estimate for shell, integration, preview, search, favourites and lock looks optimistic given the host and server issues.

Cut beat-triggered hard cuts, custom colour controls, quality tuning, favourites, thumbnails and extra preset packs unless the core is already stable. Don’t claim Windows or macOS support without testing; don’t call calm “reduced-motion-safe” or claim a global flash limit until the actual rendered output has been checked. Describe the backdrop as dependent on the tested Hermes version.

**60-second demo**

- **0–10s:** Show ordinary readable Hermes chat. Enable Aura Live; music makes the backdrop move. Caption: “Music + agent awareness.”
- **10–30s:** Give Hermes a real task that uses a tool and requests approval. Keep chat and state label visible as the backdrop changes from thinking to tool to approval. Pause briefly at approval.
- **30–40s:** Approve; show completion and its distinct visual response.
- **40–52s:** Open Studio, choose and lock a design, lower visibility; close with Esc.
- **52–60s:** Turn Aura off and show the normal readable app. End card: “Linux · tested with [actual Hermes version].”
